SwiftUI scenes

The fastest way to see a SwiftUI screen is not to launch the app at all. facetshot’s companion package, FacetshotKit, renders SwiftUI views inside a test at each device’s size and in each variant. Each view you give it is a scene: a name and a view built from sample data. facetshot runs that test and puts the screenshots on contact sheets with everything else.

Use scenes for layout: how a screen fits on a phone and a tablet, in dark mode, with large Dynamic Type. Use the simulator when you need the running app: navigation, sheets, Liquid Glass, data from a server.

SwiftUI scenes need a Mac with Xcode.

Taking screenshots

Section titled “Taking screenshots”

* matches within one part of a scene name and ** across parts, so Settings/* doesn’t include Settings/Billing/Invoice but Settings/** does.

  • iOS devices render in an iOS simulator used only to host the test; the app isn’t launched. The test bundle is built once and reused until your package’s sources change (and only one heavy build runs on the machine at a time).
  • Window devices (mac, window) render on the Mac itself with swift test. Phone and tablet sizes on the Mac are an approximation: SwiftUI gets their size classes, but controls keep their Mac look.

Variants map to SwiftUI’s environment: dark to the color scheme, large, xlarge and xxl to the Dynamic Type sizes accessibility1, accessibility3 and accessibility5, rtl to the layout direction, and locale to the locale. macOS has no Dynamic Type, so text sizes change nothing on window devices unless your views scale text themselves.

What scenes can’t show

Section titled “What scenes can’t show”

A test has no app around it, so on iOS:

  • Liquid Glass and blur are drawn flat.
  • Sheets, alerts, popovers and other windows don’t appear (on the Mac, a sheet is drawn over its window).
  • There’s no server, keychain or app state. Anything a view needs comes from the sample data you give it.

Other snapshot tools have the same limits inside a package test. Take those screens on the simulator with app: targets instead.

SwiftUI previews

Section titled “SwiftUI previews”

FacetshotKit doesn’t collect #Preview blocks automatically. Listing them at run time relies on private SwiftUI types and a prebuilt binary, which would make every app that uses FacetshotKit depend on both. Scenes are plain values, so if you already have previews, a few lines turn them into scenes. The FacetshotKit README explains more.
