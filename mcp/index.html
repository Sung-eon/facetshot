MCP tools

facetshot mcp runs an MCP server over standard input and output. AI agents explains how to connect it. This page lists every tool and parameter.

Runs go through the same background helper as the command line. Each tool below has a Returns line saying what its response holds: text, images, and for some tools the same result as structured data (structuredContent), for clients that read it. Long runs report progress as they go, to clients that ask for it.

Errors

Section titled “Errors”
  • A tool that can’t do its job (a wrong target, a config that doesn’t load, a port that’s taken) answers with isError: true and one text block: what went wrong, then what to try.
  • Screenshots that failed inside a run that went ahead aren’t an error. The summary lists them, and structuredContent.counts.failed counts them.
  • In act, a step that fails stops the steps after it. The answer is the usual view of where the screen ended up, with isError: true and failed: { step, error } (the step’s position, counting from 1, and why).
  • Sessions (open, act, close) are kept by the background helper. With FACETSHOT_NO_DAEMON set in the server’s environment (the MCP server’s form of --no-daemon), open answers with an error; capture, check and compare still work.

Names compared with the command line

Section titled “Names compared with the command line”

Some parameters have different names from the command-line options they match:

MCP parameter Command line
devices --on
variants --as
browsers, browser --browser
steps --do
against (compare) --diff, facetshot diff <name>
saveAs --save
logLevel --level
screenshot: false --no-screenshot
elements: false --no-elements

capture

Section titled “capture”

Takes screenshots and returns a summary and one contact sheet per screen.

Returns the summary as text (counts, sheet paths, failures, findings), then one JPEG contact sheet per screen (at most 4; the rest are named in a text line), and structuredContent with the run id, folder, counts, screens, grouped findings and log file paths.

Parameter Type Meaning
targets string[] what to look at: /settings, app:/inbox, story:button--primary, preview:Settings/Account, flows/x.yaml or flows/*.yaml, or an alias. Leave out to take the profile’s own targets
devices string[] devices or groups. Default: the profile’s
variants string[] variants or groups; dark+large combines. Default: the profile’s
profile string a profile from the config: its devices and variants, and its targets when none are given (Profiles)
browsers string[] the browsers for web pages: chromium, webkit, firefox, chrome, msedge, moz-firefox. Default: Chromium only; naming others replaces Chromium unless you include it
steps string[] steps played before each screenshot, written as on the command line
images sheets or none sheets (the default): one sheet per screen, at most 4 (FACETSHOT_MCP_MAX_IMAGES). none: text and paths only

To compare with an earlier run, use compare. To read a detail a sheet is too small to show, use inspect.

check

Section titled “check”

Reads screens for problems without taking screenshots. Takes targets, devices, variants, profile, browsers and steps like capture, and:

Parameter Type Meaning
checks string[] which checks to run. Default: all but a11y; ["all"] adds a11y

Returns the findings as text (or a line saying none were found), no images, and the same structuredContent as capture.

compare

Section titled “compare”

Takes the same screenshots again and returns only the sheets that changed. With no targets, it repeats the last request from this project (a capture or a check, from an agent or the command line), with the devices, variants and browsers you give here instead of that request’s. With targets, it takes only what you give here: the earlier request’s profile and steps aren’t used.

Parameter Type Meaning
targets string[] what to compare instead of the last capture
devices string[] as for capture
variants string[] as for capture
browsers string[] as for capture
against string previous (the default), a baseline name, a run id or a folder

Returns a line naming the screens that changed, the summary, the contact sheets of the changed screens only (at most 4), and the same structuredContent as capture.

inspect

Section titled “inspect”

Returns screenshots from a run, scaled to fit 1568 pixels, each with its findings, notes and log lines. With a device and a variant it returns that one screenshot. Leave either out to get the screen’s screenshots that failed, have problems or changed, at most 4.

Parameter Type Meaning
screen string, required the screen name as the summary shows it
device string the device
variant string the variant
run string a run id. Default: the latest run
region { x, y, width, height } with a device and variant: only this part, in CSS pixels or points
diff boolean return the difference image instead, if the run compared

Returns for each screenshot a text block (findings, notes, log lines) and a PNG image. No structuredContent. isError is set when the one screenshot asked for failed.

list

Section titled “list”
Parameter Type Meaning
what devices, variants, profiles, flows, checks, runs or sessions what to list. Default devices

flows lists the flow files in the project with their start and shots, and profiles shows each profile’s targets, so an agent can run a check that already exists instead of writing a new one.

Returns the list as text.

open

Section titled “open”

Opens a screen and keeps it open as a session on one device and variant, with the project’s servers, sign-in and test data: a web page, or a desktop app’s window (what sessions open). The view options below apply to this first response, as they do for act.

Parameter Type Meaning
target string, required a path (/settings) or a full URL; app:/path for a desktop app (with a window device)
device string one device. Default: the profile’s first (desktop when only browser is given)
variant string one variant. Default: the profile’s first
browser string the browser, as for browsers above. Default Chromium
elements boolean list what can be acted on, with refs. Default true
screenshot boolean return the screenshot. Default true; false responds in text only
tree boolean also return the page’s accessibility tree as text
full boolean take the whole page, not only the screen
logLevel debug, info, warn or error the least important log lines to return. Default info

Returns a view: text with the session id, address, title, log lines, console errors and failed requests, and the elements with their refs; the screenshot as a PNG (unless screenshot: false); and the same view as structuredContent (session, url, title, device, variant, image, width, height, units, logs, findings, elements, tree, failed, unsettled).

act

Section titled “act”

Does steps in an open session, in order, stopping at the first that fails. With no steps, it looks again. shot steps are ignored.

Parameter Type Meaning
session string, required the id open returned
steps string[] steps such as click:e3, fill:e4=hello, rightclick:@420,180
elements, screenshot, tree, full, logLevel as for open

Returns a view, as open does. When a step failed, the view also has failed and the answer has isError: true (Errors).

close

Section titled “close”
Parameter Type Meaning
session string, required the session to close
saveAs string a flow file for the steps that worked: flows/x.yaml (.yaml, .yml or .json, inside the project, relative to the MCP server’s folder, FACETSHOT_CWD)
keep string a new or empty folder (relative to the same folder) to copy the session’s screenshots and log into; without it they are deleted (Sessions)

Tool hints

Section titled “Tool hints”

MCP clients use hints to decide which tools to run without asking. facetshot marks inspect and list as read-only. capture, check and compare are not read-only, because they build the app, start servers, make test data, and their steps can click anything. The tools that load pages (capture, check, compare, open and act) are marked open-world, since a page can reach any site. Only act is marked destructive; but steps in capture, check and compare can do just as much, so a client set to run “non-destructive” tools without asking lets those steps run too. See Security.

Sessions the server opened are closed when it stops: when the agent closes its input, or when the server gets SIGINT, SIGTERM or SIGHUP.
